# citycenter

## What this is
John's entry in the Meta Global AI Developer Hackathon (Oct 26 to Nov 4, 2026; submission due Nov 4, 9 PM ET). A virtual city help desk for **Trust City**, an example city, not a real place. Its code and county/state map layers are the real public records of Hildale, Utah, which the Information page (`/about`) says plainly (John, 2026-11-03); the town config's `sourceName` holds the name as it appears in that data, and `lib/townconfig.js` swaps it for "Trust City" in every text value as the data loads, never in web addresses. A resident talks to cartoon desk characters. The planner reads the real code and the parcel and zoning layers and prepares a city-style application (our own layout, not the city's real form). The eight other department desks answer from the code and a catalog of sample procedures and prepare the right form. The resident signs and submits it (reports need no signature). Town staff review it in a four-step workspace (what was submitted, the code that applies, point-by-point review, return letter). Only real city officials decide; the agent never recommends, predicts or rates. See `README.md` for the judges' description.

The private planning notebook (rules digest, plan, review log, submission drafts) lives at `C:\Users\John Barlow\Projects\citycenter-notes`. Read its `notes/hackathon-rules.md` before adding any feature.

## Stack
- Node.js 22.5+ (24 in use), built-in modules only: `http`, `fetch`, `node:sqlite`, `crypto`. No npm packages, on purpose.
- Meta Model API (`lib/meta.js` is the only caller): `muse-spark-1.3` for every desk and staff step (structured output, tool calling, image input); `sam-3.1` for drawing outlines; `muse-voice-transcribe-1.0` for the microphone; `muse-wonder-1.0` for the staff second read; `muse-image-1.0` generated the characters and the office background (once, via scripts).
- Front end: plain HTML/CSS/JS in `public/`, rendered with `textContent` only (never innerHTML). The page's Content-Security-Policy blocks inline `style` attributes; set styles through `element.style`.
- Storage: one SQLite file (`data/runtime/citycenter.sqlite`, git-ignored; `/var/data` on Render).
- Hosting: Render web service, calling Meta directly (see Deploys).

## How to run it locally
1. Copy `.env.example` to `.env`; set `MODEL_API_KEY`, `STAFF_PASSCODE`, `COOKIE_SECRET`.
2. `npm start`, open http://localhost:3000 (resident) and http://localhost:3000/staff (open to everyone, no sign-in; John's decision 2026-11-03).
3. `npm test` (offline, about 30 s). `npm run test:live` (real API, about a dollar). `node scripts/journey.js http://localhost:3000` runs the whole resident-to-staff flow over HTTP. `node scripts/seed-remote.js http://localhost:3000 [ids] [--fresh]` replays the worked examples (`--fresh` first deletes earlier demo conversations).
4. A server started from an earlier session can keep holding port 3000; stop old `node server.js` processes before starting a new one.

## Where the important things are
- `server.js`: routes, limits, auth (no sign-in anywhere: the staff workspace is open to all; the staff passcode cookie now guards only `/api/staff/diag` and `/api/staff/purge-demo`; resident accounts were removed 2026-11-03; a resident visit is read or changed only with its visit code; `publicSession` removes that code and any signer address from everything the open staff side receives, and a unit test checks this), static files, relay/health/diag.
- `lib/prompts.js`: the rules every model call gets and every JSON schema (no schema may have an approval, recommendation, score or likelihood field; a unit test enforces this).
- `lib/desk.js`: the resident turn: emergency check, sketch, route (with consent before every hand-off), then the planner's understand, locate, research (tool loop), draft. `lib/servicedesk.js`: the same turn for the other eight desks. `lib/services.js`: the service catalog and its tools. `lib/tools.js`: the planner's tools over the code and the map. `lib/review.js`: staff steps (submission summary, code summary, considerations, ask, second read, letter generation and the derived letter kind).
- `lib/codestore.js`, `lib/codeparse.js`, `scripts/fetch-code.js`: the town's code from Municipal Code Online (865 sections, stored verbatim; quotes are verified against it). `lib/gis.js`, `scripts/fetch-gis.js`: Washington County zoning and Utah SGID parcels (no owner names; fictional owners come from `lib/owners.js`).

- `public/sketchpad.js`: the on-screen site sketch pad; its picture goes through the same path as an uploaded drawing. `applicationTypes[...].sketch` and `sketch` on a service decide which requests ask for one. The phone preview on desktop frames the site itself, so `lib/security.js` allows `frame-ancestors 'self'`, and nothing wider.

- `scripts/`: `deploy.js` (Render deploy), `render-env.js` (push settings from `.env.render-vars.local`), `probe-relay.js`, `probe-region.js`, `tunnel.js` (laptop fallback), `make-characters.js`, `make-office.js`, `seed.js`, `seed-remote.js`, `journey.js`, `desks.js` (plays one conversation per service through to submission; `--staff` adds the staff steps), `fetch-roads.js`, `try.js`.

## Deploys
- Render web service `citycenter` (Starter, Oregon, 1 GB disk at `/var/data`). Live: https://citycenter-puh5.onrender.com (staff at `/staff`). Health: `/api/health`. Staff-only diagnostic: `/api/staff/diag`.
- Render's auto-deploy on push does not fire for this service. After pushing, run `npm run deploy` (uses `RENDER_API_KEY` from the git-ignored `.env.render.local`).
- The live site calls Meta directly. From 2026-10-28 to 2026-11-03 it went through a Cloudflare Worker (`relay/`) because Meta's API refused most calls from Render's network. Direct calls worked 16 of 16 times on 2026-11-03, so the relay was turned off. Do not turn it back on without asking Meta first: its terms bar evading access controls. To change Render settings, edit the git-ignored `.env.render-vars.local` and run `node scripts/render-env.js --file .env.render-vars.local` (it redeploys).
- Secrets live only in `.env*` files (git-ignored) and in Render's and Cloudflare's dashboards.

## Project rules
- Core features must call Meta models. Never swap in a non-Meta model for them.
- New work only. Never copy code, data, images, docs or prompts from any other project, including anything about Colorado City or Short Creek.
- Samples are never law. Procedures, forms, fees and timelines in `services.json` are original samples: keep them in the marked sample box and keep them out of code citations. Never copy their source pages' text. Say "open license" on `/about` only where the license was confirmed; today that is UGRC's CC BY 4.0.
- This is a demo over real addresses, so nothing here may read as a real city's act: every letter carries `wording.letterNotice` from plain code, forms carry the sample footer, and no real city office address appears on them.
- Desktop must not change when the phone app changes. Put phone styling in `phone.css`, guard phone JavaScript with `isPhone()`, and keep the 18+, AI and public demo notices on the phone start screen.
- Danger right now gets the fixed line in `wording.emergency` from plain code (`isEmergency` in `lib/desk.js`) before any model runs. Keep it that way; no desk gives emergency, legal or medical advice.
- Real public data, invented people: the town's published code, the county zoning layer and the state parcel layer are real; every person, owner name, phone number and signature is invented. Never fetch, store or show real owner names. Keep the grader note about fictional owners visible.
- Public repo. No keys, passwords or personal data in any file or commit. If a key ever lands in a commit, stop and tell John so he can revoke it. GitHub push protection is on.
- Meta's Model API terms and Acceptable Use Policy apply to this app (https://dev.meta.ai/legal). Keep the desk characters labelled as AI, keep the 18+ notice and the privacy page, use Standard models only, and never strip metadata from Muse Image files.
- Three levels of help, at every department. Information: the desk shows what the code says and no conclusion. A certified question (`lib/certified.js`, packet type `certified_question`): the desk helps the resident write the question and their own tentative reading; staff answer it in writing through the same four steps, and step 3's marks choose the answer letter. A formal application: a zoning verification (which certifies a parcel's zoning or a use), a lot split, a permit and so on. A plain question must never turn into a zoning verification.
- The app never rates the applicant, predicts approval, recommends a decision, or answers "is this allowed / legal" (only a letter that staff review and send may answer). It describes what the code says, which process applies and what the paperwork needs, and quotes the code. Keep that true in prompts, schemas, code and UI text. The staff-decide line is in the town config (`wording.staffDecide`).
- Commit after each working step with a plain-English message and push to `origin main`. Never force-push. This folder is deliberately outside `Projects\` and outside auto-sync; keep it that way.
- Explain things to John in plain English; he is not a coder.
